# Template file ownership

Who owns each path in a project made from this template. `scripts/sync-template.sh`
reads this table: it updates **template** files, merges **merged** files, and never
touches **project** files. `scripts/test-hooks.sh` fails if a tracked path has no row.

- **template** — shipped and updated by the template. Don't edit it in a project:
  put the change in a project-owned file instead (see "Customising" below).
- **project** — yours. Created once from the template (or by you), never synced.
- **merged** — `.claude/settings.json`: the template owns `hooks` and `permissions`,
  the project owns `env` (and any other top-level key).

The first matching row wins (`*` also matches `/`). Keep specific rows above globs.

## Customising without forking the template

- **Rules:** add `.claude/rules/local-<topic>.md` (copy `local-example.md`). Claude
  Code loads every `.md` under `.claude/rules/` automatically; Codex is told to
  read them by AGENTS.md.
- **Hook behaviour:** only through `.claude/settings.json` → `env`
  (`DONE_GATE_CMD`, `DONE_GATE_MODE`, `DONE_GATE_ENV_PROBE`, `DONE_GATE_ENV_PORT`,
  `CONTEXT_WARN_TOKENS`, ...) and extra gates in `.claude/hooks/local/*.sh`, which
  done-gate runs after the stack's own gates.
